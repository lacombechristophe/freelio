# Suppression d'un brouillon et libération de ses temps

Le [diagnostic antérieur](../20261012-time-billing-preflight/expanded-before.json) reproduit le refus Opérations de Comptabilité. Le [lot approuvé](../../contrat-suppression-brouillon-temps-comptabilite.md) donne une autorisation limitée à `invoiceId = NULL` pour les temps du brouillon accessible supprimé par l'action Finance. Il ne permet aucune autre modification des temps.

Le brouillon et ses références sont vérifiés dans une transaction Serializable. Libération, suppression conditionnelle et audit y sont atomiques. Un document émis ou verrouillé n'est pas supprimé. Les temps gardent durée, texte, facturabilité et budget consommé ; seule leur association est libérée.

`TimeEntry.invoiceId` est un ancien identifiant sans FK. Pour refuser une libération partielle, la même autorisation permet uniquement de compter les liens vers ce brouillon déjà accessible, sans filtre de société/agence sur ce compte. Aucun identifiant ni donnée de temps étranger n'est renvoyé. Les lignes réellement libérées restent filtrées par société, client, chantier et agence ; si leur nombre diffère, toute l'opération est annulée. Les lectures ordinaires, autres comptes et autres mutations conservent leurs scopes. Cette exception est testée explicitement ; elle ne remplace pas une future contrainte référentielle avec réparation contrôlée de l'historique.

Un index de `invoiceId` borne cette recherche aux liens du document. La [mise à niveau SQLite](sqlite-index-upgrade.json) part du schéma de 1586c1b, conserve un temps historique avec référence fictive, applique uniquement l'index et vérifie son utilisation par le plan SQL. Aucun temps n'est réassocié. Les jobs PostgreSQL et Linux de a055d65 passent ; la [mise à niveau de preview](preview-index-upgrade.json) applique ensuite uniquement l'index dans la base fictive dédiée, avec données et privilèges lecteur inchangés. Cette preview contient zéro temps et zéro tâche : elle ne remplace pas le cas SQLite de conservation d'une association non vide.

Les [résultats locaux](local.json) comptent 1 980 tests / 205 fichiers, dont 36 cas de libération ; types, deux lints et build passent. Huit rôles, références étrangères, agences, liens incohérents, cinq états protégés, trois pannes, contextes, argument malformé et démo sont vérifiés. PostgreSQL coordonne une lecture réelle avec un état émis écrit par une autre transaction ; SQLite écrit cet état avant la transaction. Ce marqueur SQL ne prouve pas une émission documentaire réelle.

Les deux E2E compilés passent sur ordinateur/mobile dans chacune des CI vertes de a055d65 : annulation de la confirmation, puis suppression confirmée par Comptabilité, contrôle des temps/lignes/audit/budget et retour au formulaire des temps non facturés. Les 36 cas SQL passent aussi sur PostgreSQL. Les [résultats du candidat](../20261013-candidate/ci-a055d65.json) conservent les références ; aucun serveur local ni fournisseur réel n'est lancé. Session/cache sont simulés dans les suites SQL, les données et contraintes restent réelles.
