## Reproduction et limites

Sur une copie isolée avec dépendances installées, DATABASE_URL SQLite neuve et secrets fictifs : `node scripts/sync-prisma-schemas.mjs`, `node scripts/prepare-dev-database.mjs`, puis `node node_modules/vitest/vitest.mjs run --coverage --no-file-parallelism --reporter=json --outputFile=recette.json`. Le vérificateur `node scripts/verify-purchase-inspection-upgrade.mjs` crée sa propre base externe et ignore les identifiants applicatifs.

La fixture du test de dépôt a été corrigée : son anomalie de rejet dispose désormais d’une unité rejetée dans sa réception source, sans retrait d’assertion. Les autres diagnostics d’environnement et de lint sont conservés dans les métadonnées. Le nouveau [parcours Playwright](../../../tests/e2e/purchase-inspection-return.spec.ts) utilise une société fictive indépendante ; aucune interaction navigateur n’a été exécutée. PostgreSQL natif, Linux, charge, interruption brutale et CI du candidat restent distincts. Aucun envoi fournisseur, push, nouvelle CI, fusion ou déploiement. Les anciennes acceptations non classifiées ne deviennent pas automatiquement retournables ; leur récupération exige une preuve et une réparation séparées. Ce lot ne clôt pas tout L8/L9.
