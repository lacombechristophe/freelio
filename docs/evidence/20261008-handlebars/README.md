# Mise à jour de sécurité Handlebars

Les CI de branche et de PR de `77dbf8d` s’arrêtent sur les audits avant les tests SQLite et navigateur. PostgreSQL passe 1 246 cas, avec une exclusion native SQLite ; les huit cas de rechargement du contexte, les 22 réponses de mutation Client et les 31 synthèses par domaine passent dans les deux runs. Les neuf contrôles Linux passent aussi. Ces résultats ne qualifient pas encore le correctif Viewer dans le runtime Next compilé.

Le lockfile résout Handlebars 4.7.9. Le [mainteneur a publié 4.7.10](https://github.com/handlebars-lang/handlebars.js/releases/tag/v4.7.10), qui corrige les avis [GHSA-xw65-4hp5-5hc7](https://github.com/advisories/GHSA-xw65-4hp5-5hc7), [GHSA-8r5x-fm3f-whwj](https://github.com/advisories/GHSA-8r5x-fm3f-whwj) et [GHSA-p8wg-vrv2-v86f](https://github.com/advisories/GHSA-p8wg-vrv2-v86f). Leur publication dans la base GitHub le 8 octobre explique l’apparition du blocage après les audits précédents à zéro. Le rapport npm groupe ces avis sous une vulnérabilité de dépendance de sévérité critique.

La mise à jour porte uniquement la dépendance directe à `^4.7.10` et son entrée verrouillée. La contrainte de minimist de cette version passe à `^1.2.8` ; la version déjà verrouillée satisfait cette contrainte. Aucun seuil d’audit, test ou exclusion n’est changé. Une recherche du code applicatif ne trouve pas d’import de Handlebars : les avis ne constituent pas une preuve d’exploitation de Freelio, mais la dépendance installée doit être corrigée.

Les résultats des runs bloqués sont conservés dans [ci-77dbf8d.json](ci-77dbf8d.json). La recette locale utilise une copie isolée, le lockfile mis à jour, des données fictives et aucun fournisseur. Les contrôles après mise à jour et les nouveaux résultats navigateur doivent être distingués de ces runs bloqués.

La correction est dans `8efecb8`. Les [contrôles locaux](local.json) passent types, ESLint/Oxlint, 1 247 tests SQLite dans 171 fichiers et build de 75 pages. Les deux audits de l’installation physique sont à zéro et son lockfile est identique à celui du candidat. PostgreSQL est validé sans connexion ; les 244 E2E dans 46 fichiers sont découverts, sans navigateur local. Les empreintes des logs, du lockfile et des fichiers hors documentation sont conservées. Le contrôle de publication inspecte 1 070 fichiers et 3 107 blobs historiques, sans résultat bloquant ; sa portée reste celle des motifs recherchés.
