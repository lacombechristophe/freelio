Le formulaire transmet sa révision et conserve ses données en cas de refus. Les refus attendus sont renvoyés comme données par la façade [Asset Commands](../../../src/actions/asset-commands.ts) ; une erreur technique inattendue reste confiée au traitement d’erreur de production.

## Limites et reproduction

Le présent lot crée le brouillon. L’envoi à signature, la signature et le lien entre les conditions signées et la décision d’un futur terme restent à reproduire et qualifier séparément ; ce lot ne les clôt pas. Les anciennes propositions ne sont ni réparées ni recalculées. Les autres politiques d’état, le Centre de support principal et les derniers sélecteurs restent distincts. PostgreSQL, Linux, navigateur, CI distante et déploiement du SHA exact restent requis avant fusion. Aucun schéma, dépendance, installation, matrice de rôles, algorithme d’archive, licence ou envoi fournisseur ne change. Aucun push ni déploiement : le plafond GitHub Actions à 0 € avec arrêt de l’usage payant reste à attester.

Dans une copie déjà installée, fournir une configuration fictive et une DATABASE_URL SQLite neuve, puis préparer avec `node scripts/prepare-dev-database.mjs`. Lancer `node node_modules/vitest/vitest.mjs run tests/unit/maintenance-proposal-integrity.integration.test.ts tests/unit/maintenance-renewal-integrity.integration.test.ts tests/unit/maintenance-settings-integrity.integration.test.ts tests/unit/operations-service-directory.integration.test.ts tests/unit/asset-reference-lifecycle.integration.test.ts tests/unit/maintenance-renewal.test.ts tests/unit/asset-commands.test.ts tests/unit/quote-contract-conversion.integration.test.ts tests/unit/public-demo-database.integration.test.ts tests/unit/public-demo.test.ts tests/unit/contract-archives.integration.test.ts tests/unit/structured-contract-documents.test.ts --no-file-parallelism`. La suite complète utilise run --coverage --no-file-parallelism, sans build parallèle.
