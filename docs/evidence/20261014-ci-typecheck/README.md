# Qualification interrompue au typage

Les deux CI de 87c70a1 échouent à l'étape TypeScript, après génération des types Next. V8 atteint environ 2 000 Mo puis s'arrête par manque de mémoire. Les tests SQLite, le build du job qualité et les parcours navigateur ne sont donc pas exécutés ; leurs résultats restent inconnus. Les [rapports conservés](ci-87c70a1.json) distinguent cet arrêt des contrôles réellement passés.

PostgreSQL réussit 2 345 tests sur la branche, avec une exclusion native SQLite ; les 35 cas de choix Achat et 24 cas de création passent sans exclusion. Le job PostgreSQL de la PR n'atteint pas les tests : le registre ECR refuse les trois téléchargements du service avec `toomanyrequests: Data limit exceeded`. Les neuf contrôles Linux passent dans les deux CI. Les deux audits de dépendances passent dans chaque job qualité.

Le manque de mémoire est reproduit localement avec un plafond V8 de 2 048 Mo. Le même compilateur, sur les mêmes sources, passe avec 4 096 Mo : [mesure](typecheck-memory.json), 2 617 056 Ko utilisés et 30,54 secondes. La commande typecheck conserve la génération Next et tous les fichiers contrôlés ; seul le plafond du processus TypeScript devient explicite. Aucun délai, assertion, seuil de couverture ou d'audit, sélection de tests ou budget mémoire du serveur n'est modifié. La commande npm complète est également exécutée après changement.

La preview Vercel de 87c70a1 est bloquée car le fournisseur ne rattache pas l'auteur du commit à un compte Git. L'API GitHub retourne également un auteur non associé pour l'adresse de contact utilisée. Le prochain commit emploie l'adresse `noreply` avec l'identifiant du même compte, selon la [documentation GitHub](https://docs.github.com/en/enterprise-cloud%40latest/account-and-profile/reference/email-addresses-reference). La configuration globale et les commits publiés sont conservés. L'association GitHub et la preview devront être vérifiées après publication ; ce changement de métadonnées ne prouve pas à lui seul un déploiement réussi.
