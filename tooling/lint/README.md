# Règles de lint conservées

Le 8 octobre 2026, `eslint-config-next@16.3.6` apporte `fast-glob → micromatch → braces`, sans version corrigée pour [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). Cette configuration est remplacée par les mêmes versions des plugins React, React Hooks, TypeScript, import et accessibilité, avec les mêmes niveaux et exceptions. Oxlint 1.87.0 porte 21 règles Next ; son groupe automatique de règles est désactivé au profit de cette liste explicite. Les deux moteurs sont obligatoires dans `npm run lint`.

`baseline-rules.json` conserve les règles résolues avant migration pour une page TSX, un module TS et un script MJS. `next-rule-cases.json` conserve les 21 fautes détectées par l’ancien moteur dans une arborescence Next de recette. Les tests comparent la politique combinée et vérifient chaque détection, ainsi qu’un fichier sans faute. Cela ne prétend pas à l’équivalence de toutes les implémentations : Oxlint détecte aussi des ancres internes dans App Router et les doubles Head de composants fonctionnels que l’ancien plugin laissait passer.

La règle manquante `no-location-assign-relative-destination` est dérivée de la [source officielle v16.3.6](https://github.com/vercel/next.js/blob/v16.3.6/packages/eslint-plugin-next/src/rules/no-location-assign-relative-destination.ts). Transformation : suppression des types via TypeScript et remplacement de l’utilitaire d’identité `defineRule` par son équivalent local. La logique est conservée et sa [licence MIT](NEXT-LICENSE.md) accompagne le fichier. La copie est limitée à cette règle ; elle devra être revue lors d’un changement de version Next, ou retirée quand Oxlint la prend en charge avec une recette équivalente.

Les liens d’export portent explicitement `download`, comme les réponses serveur `Content-Disposition: attachment`. Il ne s’agit pas de navigations entre pages. Aucun bouton ni style n’est changé. Aucun contrôle de sécurité, seuil d’audit ou contrôle React n’est retiré.
